融合架构图

同一批实时工艺参数，喂给两个模型：一个凭经验判断结果，一个按物理判断过程。在边缘侧先把关、再建议、最后由人放行。

输入层 · 边缘采集

按箱体条码 + 时间戳对齐，缺失即标「不适用」

实时工艺参数 — 每箱必接

经 PLC / S7 网关或 IoT 平台进入边缘，是两个模型共同的「眼睛」。

料比料温注料重量 / 压力模芯温度夹具温度环境温湿度发泡 / 固化时间
关键：要过程轨迹，不要单个终值。模温在固化 300 秒里是稳住还是中途掉 3℃，算出的固化度完全不同。

静态配置 — 研发端下发

不常变的参数存在边缘，换产品、换料时换一版，机理靠它重算可行域。

反应动力学黏度 / 导热发泡剂特性产品结构模具结构
研发给的固定可行域表也放在这一层，做硬护栏——便宜、可解释、好验证。

2

双模型层 · 同输入，不同输出

输入一样，看的东西完全不一样

机理模型 · 像物理课本

按物理，划红线

反应 — 传热 — 发泡 / 固化机理，做成可上边缘的降阶模型。在固化过程里边算边更新，不等检测时才算。

输出 · 过程进行到哪了、能不能这么调
  • 关键过程状态固化度、反应转化率、温度趋势、发泡压力、易出气泡 / 空洞的位置
  • 动态可行域 + 调整约束结合本箱环境与料性算出：还能调多少、单次步长上限多少
  • 适用性标识在不在适用范围、可不可信；超范围标「不适用」

料温 / 模芯 / 夹具18–28℃ / 35–55℃ / 30–50℃

安全基线1.08 · 22℃ · 45℃ · 360 s
✓ 没数据也能给底线，换批次、换产品不易被带偏，能说清「为什么不行」✕ 只是简化模型，算不准精确缺陷概率，也抓不到设备磨损这类经验因素
数据模型 · 像老师傅

凭经验，猜结果

LightGBM 小模型，学历史每箱参数与热成像 NG 标签的规律，专抓非线性与组合效应。

输出 · 结果会怎么样、该往哪调
  • 缺陷概率 + 判定概率 ≥ 0.50 判 NG；这是它的核心输出
  • 置信度低于 0.70 就不自动走，转人工 / 大模型辅助判断
  • 建议参数 + 目标分在允许范围内，给出它认为最划算的一组参数
  • 影响因子这次主要是谁在拖后腿，如料温与模芯温度
最擅长料冷 + 模芯冷一起出问题，这类组合规律规则写不出来，它能从历史 NG 里学到
典型输出概率 0.8155 · 高风险
✓ 能学到规则写不出的规律，预测细、反应快✕ 没见过的情况会瞎猜；数据少、标签脏就不可信；讲不清物理原因
二期增强

真正的融合，不只是串联把关：机理算出的固化度、反应程度、温度趋势，作为特征喂给数据模型。数据模型不必再从头学物理，只学「机理算不准的那部分残差」——样本少也好用，换批次外推也更稳。一期先用「机理把关 + 数据建议」过验收，二期再升级到这一步。

3

融合决策层 · 顺序不能反

先让机理把关，再听数据的建议

三道关，缺一不可

最终下发参数必须同时满足两边：在机理的框里，而且数据模型算出来缺陷概率最低。

第 1 关 · 否决

机理先审

建议参数一出可行域 / 白名单，直接否决，不下发。例：数据想把模芯提到 58℃，上限 55℃、白名单只到 52℃ —— 拦截。

第 2 关 · 评估

数据再评

在可行域内，数据模型给缺陷概率与建议值，判断这组参数到底好不好，而不只是合不合格。

第 3 关 · 兜底

冲突找人

两者打架、置信度 < 0.70、或超出历史分布，一律转人工 / 大模型辅助，不自动下发。

域内多目标优化在可行域 + 白名单内搜索（料比 1.00–1.12 · 料温 19–27℃ · 模芯 38–52℃ · 固化 240–540 s）同时算：质量 · 料耗 · 能耗不再是「一律往中心靠」
4

输出与执行层 · 人来放行

大模型不直接控 PLC，建议必须过校验、经确认

双确信 · 一致

建议参数 → 受控下发

依次过 8 项安全校验、人工确认，再下发并做读回验证，留审计与回滚记录。

有风险 · 存疑

只提示，不下发

机理说能过、数据说危险（如五参数都贴边），判 NG 转人工复核，不走受控自动。

不可行 · 不适用

拦截并留痕

越界、超适用范围或数据缺失：禁止自动下发，只出风险提示并报警留痕。

超时降级，不堵产线：机理仿真超时或异常时，先出热成像结果 + 静态规则与数据模型的判断，本箱标「不适用」，算力恢复后再补算 —— 不因系统导致停线。

同一箱，两种输出

输入完全相同，看两个模型分别说了什么，最后怎么合到一起。

料比1.10料温19.0℃模芯38.0℃夹具42.0℃固化300 s环境26℃

数据模型说：结果不好

缺陷概率 0.8155

判高风险。主要拖累因子是料温与模芯温度，建议往 1.0875 / 21.0℃ / 41.5℃ / 345 s 调，目标分 0.5447。

＋

机理模型说：过程不对

固化度偏低

料温 < 20℃ 且模芯 < 40℃，反应慢、传热不够，有欠发泡风险；上述建议仍在可行域内，允许调整。

融合结论：两者一致指向同一问题 → 采纳建议参数 1.0875 / 21.0℃ / 41.5℃ / 345 s，人工确认后模拟下发。

三条边界，记住就行

分工说到底是边界问题：谁能做什么、谁不能越过谁。

01

机理管「能不能」，数据管「好不好」

机理是裁判，决定一组参数可不可行；数据是参谋，决定可行范围里哪组更好。

02

谁也不能替对方干活

机理不能替数据做精细缺陷预测；数据再确信，也不能推翻机理、越界下发。

03

拿不准，就不自动

两者冲突、低置信度、超出分布、超出适用范围 —— 一律不自动下发，转人工。

现状说明：上图是设计目标。当前正式系统中，机理侧仍是约束框架（只判在不在框、违反哪条），固化度等过程状态尚未真正算出；数据侧训练模型槽位（LightGBM）已注册但未接入，融合的验证指标尚未用冻结数据集验证。因此分工为设计分工，落地按「一期串联把关过验收、二期残差融合提质量」推进。静态研发规则与机理仿真并不等效：前者在安全拦截上效果接近，但在预测、优化、换产品与根因分析上差很多，故两者分层共存。
